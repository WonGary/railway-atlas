# 铁道漫游：数据调查与首版实现

调查日期：2026-11-08，Asia/Shanghai。此文区分已经核对的资料、已经实现的功能和仍待获取的数据。版本目标：0.3.0 (16)。

## 路路通的数据从哪里来

直接读取了路路通官网、官方常见问题和开发者在 App Store 提交的产品说明。

- [官网](http://www.lltskb.com/)及[Android 产品说明](http://www.lltskb.com/android1/lltskb.html)：提供离线时刻查询和数据库在线更新，也提供联网余票、票价查询。
- [官方解释：路路通时刻表是如何工作的](http://wap.lltskb.com/wtfk/2.html)：明确区分两种数据。离线数据随数据库更新；联网查询和购票通过访问 12306 网站、简化网站界面完成。这能解释联网部分的来源，**不能据此断定离线库的上游或授权关系**。
- [官方解释：查询不到车次或时刻与实际不符](http://wap.lltskb.com/wtfk/11.html)：列举隔日开行、跨零点抵达中间站以及某个日期前后临时调整的例子。这证明其模型考虑开行日期和临时变化，**不证明它拥有可查询的完整历年运行图**。
- [App Store 官方产品元数据](https://itunes.apple.com/lookup?id=756812216&country=cn)：说明离线查询、联网查询和定期数据更新；本次返回的更新说明为离线库更新到 2026-11-05。

本次官网显示数据库日期为 **2026-11-14**，晚于调查日 **2026-11-08**。只记录其页面标签，不将它认作今天已经生效的运行图。官网首页和 Android 介绍页的软件版本号也不一致，不能把页面标签当成统一的版本证明。

没有找到其公开的离线数据上游、向第三方分发的授权说明、稳定开放 API 或完整历史库覆盖清单。没有联系开发者、下载/拆解 APK、复制其数据库或接入账户。若采用它作为数据供应方，下一步应确认：供应形式、许可、历史年份、服务日和临时调整、全程停站、车次变更、错误更正、更新频率及停服后的本地使用权。

## 12306 与个人乘车历史

本次直接核对官方现行网页：

- [火车票订单页](https://kyfw.12306.cn/otn/view/train_order.html)：提示订单信息在该网站保存 30 日。这是网站可查询订单的规则，不是对铁路内部数据留存期限的判断。
- [电子发票业务须知](https://kyfw.12306.cn/otn/view/invoice_index.html)：乘车日期为 2025-10-01 及之后，符合条件的业务可在行程结束或支付退票、改签费用后 180 天内开具；可直接下载或用邮件接收。跨境等例外也在该页说明。**开票期限不等于历史订单保留期限，发票也不独立证明已乘坐。**

可行产品路线：

1. 首次导入：把已经留存的票据图片、截图、PDF、短信/邮件文字、CSV 放进同一个核对流程。先提取，再批量筛选、去重、补缺项；不要求逐条从空白填表。
2. 旧记录：由保存过的邮件、报销资料、纸票和用户自己在购票平台取得的记录补齐。无法取得的日期/车次留空待核对，不能从今天的时刻表反推旧车次。
3. 此后积累：保留本地护照与可迁移的 JSON 备份。未来可增加用户主动启动的订单页面导出、邮件文件夹导入和可选设备间同步；不要依赖一个永远可回溯的 12306 账户接口。
4. 状态分离：待核对、已乘坐、未乘坐。只有用户明确确认的已乘坐记录计入护照统计。退票、改签、代购和未出行都不能仅凭支付凭据算作旅行。

首版已实现本机 Vision 图片识别、PDF 文字读取和扫描页识别、文字提取、UTF-8 CSV、JSON 备份导入；带导入预览、重复候选默认排除、编辑、删除撤销和上版文件备份。图片/PDF/OCR 不保证识别全部版式，字段不足会要求补齐。不会读取整个邮箱、登录 12306、保存姓名证件号或上传原票。用户自行填写的备注属于本地个人资料。

目前没有账户自动同步、后台邮箱同步或 iCloud 同步。JSON 导出/导入是已交付的跨设备迁移方式。

## 五项功能的实现范围

### 路网猜城市

使用随包 OSM 城市轨道概览中的 16 城线形，无须在答题中联网。独立窗口与主地图选择无关。统一线色，移除底图、语言、站名、线路编号、坐标、比例尺、真实线色和可点击的站点详情。画布入参只有归一化的 `x/y`，无字符串或来源标识。可为下一题随机旋转，答题后才显示答案和具体快照日期。

保留通用 OSM 署名。此设计防止界面泄题，不把一个离线应用描述为能抵御解包或内存检查的竞技防作弊系统。题库可能缺线，不宣称完整现实路网。

### 铁路护照

使用独立 `RailwayAtlas/Passport/journeys-v1.json`，不改动收藏、地图缓存或 GPT 配置。写入前验证，原子替换，保留 `journeys-previous.json`。损坏文件保持原样并进入只读状态。

JSON 备份可保留已确认状态；CSV、文字和 OCR 生成的记录默认待核对。相同日期、车次、起终站和发车时刻作为重复候选，导入前允许用户保留独立记录；不把不明确的重复直接删除。

### 地图明信片

三种样式：红票、蓝票、城市线形明信片。红票使用 `STSongti-SC-Bold`，蓝票使用 `STHeitiSC-Medium`，数字使用 `Menlo-Regular`；缺少相应字体时使用系统字体回退。没有将 Windows 铁路票面字体随应用打包。

支持从护照带入行程、修改寄语和选择城市线形，输出 1520×880 PNG。城市图形不是车次运行径路；纪念设计带“非乘车凭证”小字，不附可用购票二维码、乘客身份或铁路认证信息。明信片上的编辑不会回写护照。

### 铁路时光机

首版是可播放、可拖动、有逐条来源的 **9 个历史节点**，并接受带来源的自定义节点包。事件日期与文章发布日期分开；来源只给月份就保留月份。示意图中的位置为城市中心，虚线仅表达城市关系，未假装还原轨道级历史网络。

下一阶段要实现真正的历史路网，应分别建表：

- 线路分段和车站：稳定身份、旧名、启用/停用/迁移日期及日期精度。
- 几何快照：每条几何自己的有效时段与出处，不让旧年份直接复用今天的轨道。
- 服务快照：当期车次、径路、停站、开行日与到发时刻。
- 原始证据：运营方公告、铁路志、档案地图、正式时刻表及其版本。

不能把 OSM `opening_date` 简单套到整条当前线路：一条 relation 的不同区段可能分期开通、改线，车站也会迁移。OSM 的历史编辑日期也不是铁路开通日期。未收录的铁路不能画成“当时不存在”。

## 文件接口

护照 CSV（UTF-8；支持逗号、引号、换行字段；中文表头也可）：

```csv
date,train,from,to,departure,note
```

JSON 备份版本为 1；个人记录字段为 `id,date,train,from,to,departure,status,source,note`。

时刻包：`{"version":1,"timetables":[...]}`。每趟车有唯一 `id`、`train`、`serviceDate`、IANA `timeZone`、`source` 和有序 `stops`。到发时刻为从始发日零点起累计分钟；次日 01:20 为 1520。缺少的到达或出发用 `null`，不能复制相邻时刻补齐。参考随附资源 `railway-experience-timetables.json`。

历史节点包：`{"version":1,"events":[...]}`。每个节点有唯一 `id`、`date`、`title`、`detail`、编辑示意 `places` 和 `source`。日期可为年、年月、完整日期；来源必须提供名称、URL 和查阅日期。参考 `railway-experience-history.json`。

导入时刻与历史节点会保存到独立 `RailwayAtlas/Experiences` 目录，保留前一版。重复标识会报错，避免静默覆盖旧证据。外部包的来源字段是导入者的声明，不代表应用完成了对其真实性的独立核验。
