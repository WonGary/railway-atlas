# 全线高亮取景

从 `9353468` 验证。跨度取轨迹投影的宽、高分别除以可见地图的宽、高，再取较大值。站表首次定位使用站点范围，轨迹到齐后用站点和轨迹的并集重新计算。每次都用原始坐标计算一次 80%。

| 入口 | 实际检查的坐标 | 实测最大跨度 | 越界点 |
|---|---:|---:|---:|
| Web 郑州站展开陇海线、再点地图查看 | 2,858 个轨迹顶点及 60 个站点 | 80.00% 至 80.09% | 0 |
| Web 点击上海包的沪昆线区段 | 4,705 个目录轨迹顶点 | 80.00% | 0 |
| Web 点击北京地铁 18 号线、站点方向按钮 | 两方向各 140、136 个轨迹顶点，另各 11 站 | 80.00% 至 80.02% | 0 |
| macOS Canvas、MapKit 选沪昆线 | 4,723 个坐标，含点击的上海区段 | 80.00% | 0 |
| macOS Canvas、MapKit 选北京地铁 18 号线马连洼往天通苑东 | 140 个轨迹顶点及 11 站 | 80.00% | 0 |

Web 用浏览器鼠标点击实际轨道和按钮。1440 × 900 桌面覆盖左右浮动、停靠的四种组合。在 390 × 844 窄屏，工具栏和底部信息栏之间实测有 390 × 457 像素。手动平移后收起浮动信息栏，地图保留平移位置。

原生测试使用现场窗口的侧栏边缘、MapKit 坐标转换和 Canvas 绘图投影。每个渲染器、每条线路检查六次，含 1240 × 820 的四种布局，以及 960 × 700、界面缩放 160% 的窄窗口。此次运行窗口处于后台，四次点线都将地图屏幕坐标送入实际点击处理函数。前台运行时，脚本会在确认目标窗口位于点击位置后发送鼠标事件。iPhone 模拟器验收待做。

复测命令为 `node Portable/check-line-viewport.cjs` 和 `bash Portable/check-line-framing-native.sh`。前者需要 `playwright-core` 和 Chromium 或 Edge。后者使用工作树里的临时 `.app`，输出 `.build/framing-run.*/receipt/line-framing.txt`。
